# egg-demo

Демо-проект для знакомства с библиотекой [egg](https://github.com/egraphs-good/egg)
(Rust, версия 0.11) — реализацией **e-graph'ов** (эквивалентностных графов)
и алгоритма **equality saturation**.

## Что такое egg

**egg** — это библиотека на Rust для работы с e-graph'ами. E-graph — это
структура данных, которая хранит выражение не как одно дерево (AST), а как граф
всех *эквивалентных* представлений этого выражения:

- одинаковые подвыражения представлены одним узлом (класс эквивалентности,
  "e-class" = *equivalence class*);
- правила переписывания применяются не как в обычном терм-райтере (применить
  правило = заменить и *выбросить* старое), а как добавление нового равенства
  в граф. Ничего не теряется.

Процесс: применяем правила, пока можно (до "насыщения", saturation), затем
извлекаем (extract) из графа лучшее выражение по заданной стоимости
(например, минимальный размер дерева). Это и есть **equality saturation**.

Один из главных приёмов — **конгруэнтное замыкание**: если `a = b` и `b = c`,
то `f(a,b) = f(a,c)` для любого контекста `f`. Именно он позволяет правилам
"срабатывать" внутри подвыражений, а не только на верхнем уровне.

## Что делает демо

`src/main.rs` состоит из двух частей:

1. **Конгруэнтное замыкание** — вручную добавляем в e-graph узлы
   `f(a,b)`, `f(a,c)`, объявляем `a = b`, `b = c` и смотрим, что после этого
   `f(a,b)` и `f(a,c)` оказываются в одном классе эквивалентности.
2. **Equality saturation** — задаём правила упрощения арифметики
   (`x + 0 = x`, `x * 1 = x`, `x + x = 2x`, коммутативность и т.д.) и запускаем
   `Runner`, который насыщает граф, а `Extractor` извлекает минимальное
   выражение.

Запуск:

```sh
cargo run
```

Ожидаемый вывод:

```
=== Часть 1: конгруэнтное замыкание ===

f(a,b) и f(a,c) в одном классе? false
После a=b, b=c: f(a,b) и f(a,c) в одном классе? true
Всего классов эквивалентности: 2

=== Часть 2: equality saturation ===

Исходное выражение: (* (+ 0 (* 1 a)) (+ b b))
Итераций: 7, классов эквивалентности: 9, узлов: 35
Упрощённое выражение: (* a (+ b b)) (стоимость 5)
```

## Визуализация

Программа сохраняет e-graph в виде картинок в папке `viz/` (модуль `src/viz.rs`):

| Файл | Что показывает |
|---|---|
| `part1_before` | e-graph до объявления равенств: `f(a,b)` и `f(a,c)` — отдельные классы |
| `part1_after` | тот же граф после `a=b`, `b=c`: классы слились, видно конгруэнтное замыкание |
| `part2_start` | исходное выражение `(* (+ 0 (* 1 a)) (+ b b))` |
| `part2_iter2` | граф после 2 итераций правил — появляются новые эквивалентные формы |
| `part2_final` | насыщенный граф: все эквивалентные формы выражения в одном графе |

Каждый файл сохраняется в трёх форматах: `.dot` (исходник GraphViz), `.svg` и
`.png`. Прямоугольники на картинках — e-классы (классы эквивалентности),
эллипсы — e-узлы, стрелки ведут из узла к классам его детей.

Для рендера нужен бинарник `dot` (Graphviz). Программа ищет его в переменных
окружения `GRAPHVIZ_DOT` / `GRAPHVIZ_BIN`, затем в PATH. Если его нет —
сохраняются только `.dot` файлы (их можно открыть, например, в
[webgraphviz.com](https://webgraphviz.com/) или плагине VS Code).

*Примечание:* предупреждения Graphviz вида `tail is inside head cluster`
безобидны — это известный косметический дефект рендера self-edge у e-классов.

## Откуда взялась популярность

- Идея equality saturation: Tate et al., POPL 2009.
- **egg**: Max Willsey, Chandrakana Nandi, Yisu Remy Wang, Oliver Flatt,
  Zachary Tatlock, Pavel Panchekha — *"egg: Fast and Extensible Equality
  Saturation"*, POPL 2021 (отсюда и название — e-graphs + egg).
- С тех пор e-graph'ы плотно применяются в оптимизирующих компиляторах
  (включая deep learning и линейную алгебру), SMT-солверах (Z3, CVC4),
  супероптимизации, верификации и синтезе программ. Авторы egg сделали
  наследника — **egglog** (Datalog-подход к e-graph'ам), а также
  продолжающийся рерайт **egg2**.
